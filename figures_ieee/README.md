# IEEE INFOCOM-formatted figure exports

Every figure built during this project's report-writing (24 total, across the RNN vs CNN
comparison, fingerprinting-performance, and confusion-matrix reports) exported as
publication-ready files, three per figure plus the intermediate source:

- **`.pdf`** — vector, use this for `\includegraphics` in the LaTeX manuscript
- **`.eps`** — vector, Encapsulated PostScript, for toolchains that still want it
- **`.png`** — raster, 600 DPI, for quick preview or non-LaTeX use
- **`.svg`** — the resolved, standalone intermediate (kept for re-editing)

## Specification applied

- **Font**: Times New Roman, substituted with the installed metric-compatible
  equivalent (Liberation Serif / Nimbus Roman — both are certified drop-in
  replacements for Times New Roman; actual "Times New Roman" is a proprietary
  Microsoft font not present on this Linux machine, so PDF/EPS output embeds
  Liberation Serif, which renders identically at the same point sizes).
- **Label size**: every figure's axis/tick/legend text is scaled to land at
  **8.5pt** at final print size — the original charts were authored as
  on-screen SVGs at arbitrary pixel scale, so this is computed per figure
  (target 8.5pt ÷ that figure's own median embedded font-size = the scale
  factor), not just a uniform resize. This keeps every figure legible and
  visually consistent even though they were originally drawn at different
  pixel scales.
- **Width**: capped at **7.16in (516pt)** — IEEE INFOCOM's two-column page
  full text width (the `\figure*` double-column maximum, from the IEEEtran
  conference template: two 3.5in columns + 0.2in gutter ≈ 7.2in). Most
  figures in this set are dense (dual RNN/CNN panels, legends, many data
  labels) and need the room; a few (individual confusion matrices) came out
  narrower than the cap because their original font sizes already needed
  less scaling to hit 8.5pt.
- **Background**: solid white (the on-screen versions use a light theme
  background token that isn't pure white; papers print on white stock).
- **Colors**: resolved from the reports' on-screen CSS custom properties to
  their literal light-theme hex values (a standalone SVG file has no CSS
  cascade to resolve `var(--name)` against, so this had to be done explicitly
  or the color would be lost).

## Source

Generated by `export_ieee_figures.py` (kept in the session scratchpad) from
the raw SVG fragments each report's `build_fig*.py` script produces. Re-run
that script any time the underlying charts are regenerated with new data —
it always re-derives colors/fonts/sizing from the current fragment content,
nothing here is hand-tuned per file.
