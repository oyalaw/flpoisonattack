FL_poison testbed — as-built, post 8th-fix

System Architecture & Poisoning Algorithm

The network-layer man-in-the-middle poisoning testbed: a passive phase-inference control plane that decides when to attack, and an in-line proxy data plane that decides what to inject and how to hide it from the active Byzantine-robust defense.

System Architecture

Two independent planes share the same wire. The control plane (purple, UDP, out-of-band) only ever tells the proxy when a client is uploading. The data plane (blue, gRPC/HTTP2 over TCP, in-line) is where the actual interception, reconstruction, poisoning, and stealth projection happen. The server never sees either plane — it is attack-blind by construction (server_attack_knowledge: false).

analyzer.py

Network Analyzer

Sniffs the shared interface for every client's TCP flow. Runs a per-client HMM (adaptive_emission) over byte-share features to infer {IDLE, DOWNLOAD, TRAIN, UPLOAD}, latches the state with hysteresis (update_stable_state/commit_phase_transition), and on a confirmed UPLOAD dispatches a UDP trigger (maybe_trigger_attack → dispatch_attack_command). Never touches the wire.

poison_live.py

Poisoning Proxy

Transparent in-line MITM between clients and server. Acts as the server to clients and as a client to the real server. Consumes analyzer triggers via evaluate_phase_gate; for the target under an open, fresh gate it intercepts, reconstructs, poisons, and re-serializes; every other client is forwarded byte-identical.

peer_fingerprint.py

Peer Fingerprint Registry

Accumulates a sketched (or, budget permitting, full-block) geometry of every non-target client's genuine update per round — the peer distribution the boundary-optimized attacks need but never gets from the target's own update alone.

selection_attacks.py

Attack Engine

Computes the raw poisoned update. Trivial attacks (sign_flip, scale, noise) transform the target's own genuine update; boundary attacks (craft_min_max, craft_min_sum, craft_selection_optimal) search for the most damaging update that still looks admissible against the peer geometry.

stealth_projection.py / envelope.py

Stealth Envelope

Projects the raw poisoned update into a per-coordinate / per-tensor-norm / direction-concentration envelope derived from the target's own observed genuine updates, blended by an aggressiveness parameter (0 = fully benign-looking, 1 = raw attack) before the update is re-serialized onto the wire.

server_v8.py

FL Server (attack-blind)

Ordinary Flower server running one of six aggregation rules. Receives only re-serialized, wire-valid updates and has no knowledge that a proxy exists (server_attack_knowledge: false, server_receives_attack_target_ids: false) — this is what makes the testbed's attack-execution funnel measurements meaningful.

Algorithms

Pseudocode transcribed directly from the current codebase (function names and gate ordering match the real source, not a simplified retelling), reflecting the state after all eight bugs found and fixed this investigation.

Algorithm 1 — Phase-Gated Attack-Trigger Dispatch

analyzer.py :: maybe_trigger_attack()
# runs once per sniffed packet, per client_id
function maybe_trigger_attack(client_id, packet):
    features   ← compute_features(client_id, packet.ts, packet.size, packet.direction)   # byte-share, not packet-count
    belief     ← adaptive_emission(client_id, packet.direction, features, packet.iat, packet.size)
    state      ← update_stable_state(client_id, argmax(belief), confidence(belief), packet.ts)  # hysteresis-latched
    commit_phase_transition(client_id, state)

    # --- gate chain, evaluated in this exact order ---
    if startup_grace_active:                     reason ← "startup_grace_active";        return skip
    elif client_attacked_this_round(client_id, round): reason ← "already_attacked_this_round"; return skip
    elif cooldown_active:                        reason ← "cooldown_active";             return skip
    elif not should_trigger_attack:              reason ← "phase_not_confirmed";      return skip

    dispatch_attack_command({client_id, round, phase: "UPLOAD",
                              confidence, ttl: POISON_TRIGGER_TTL_S})   # UDP → proxy
    mark_attacked_this_round(client_id, round)

# should_trigger_attack is a 2-path OR: an early fast-path for the common
# case, and a fallback that no longer requires proxy-only wire artifacts
should_trigger_attack ← strong_outbound_upload_start   # TRAINING→UPLOAD release, high packet_support_score
                       or confirmed_upload_phase        # decision_phase==UPLOAD and direction==outbound
                                                     #   and packet_size >= PHASE_MIN_PAYLOAD
                                                     #   (outbound_share>=0.70 clause removed: see note)
Gate-ordering note: the chain is evaluated top-to-bottom and short-circuits on the first true condition — a client failing should_trigger_attack never even reaches the cooldown/dedup logic on a later packet until the earlier gates re-open. The outbound_share ≥ 0.70 clause inside confirmed_upload_phase is struck through above because it is dead weight, not a typo: it was measured to be a hard, uncrossable ceiling for every genuinely transparent (non-rewritten) client — only the proxy's own target-rewrite traffic could ever clear it. This was the 8th and decisive fix.

Algorithm 2 — In-Line Poisoning Injection

poison_live.py :: forward_upload()
# runs on every intercepted gRPC/HTTP2 DATA frame from a client
function forward_upload(client_ip, message):
    if client_ip != active_analyzer_target:
        record_peer_observation(peer_registry, client_ip, message)   # sketch/full-block, no mutation
        return forward_unmodified(message)                     # transparent pass-through

    open, reason, snapshot ← evaluate_phase_gate(client_ip, required_phase="MODEL_UPLOAD")
    # snapshot freshness checked against phase_gate_max_age_s (90s);
    # confidence checked against phase_gate_min_confidence (0.85)
    if not open:
        return forward_unmodified(message)

    genuine   ← reconstruct_tensor_update(message, model_contract)   # hash + shape/dtype validated
    peers     ← peer_registry.geometry_for_round(current_round)      # needs ≥min_peers observations
    raw       ← craft_attack(attack_type, genuine, peers, aggressiveness)   # Algorithm 3
    envelope  ← envelope_from_history(client_ip)                     # this client's own recent genuine updates
    projected ← project_update_into_envelope(raw, envelope, aggressiveness, k_coord=3.0, k_norm=3.0)

    wire_msg  ← reconstruct_wire_message(projected, model_contract)
    log_attack_event(genuine, raw, projected, snapshot)             # -> proxy_attack_events_*.csv
    return forward(wire_msg)                                      # server receives a wire-valid, unlabeled update
Why the server can't tell: reconstruct_wire_message re-derives every transport-level property (content-length, HTTP/2 flow-control frames, message contract) from the projected tensors, so the poisoned message is indistinguishable on the wire from a genuine one of the same shape.

Algorithm 3 — Boundary-Optimized Attack Crafting

selection_attacks.py :: _search_distance_boundary()
# used by min_max and min_sum; krum_optimal follows the same shape against
# Krum's own scoring function instead of a distance threshold
function _search_distance_boundary(peers, mode, strength):
    peer_mean  ← mean(peers)
    direction  ← harmful_direction(peer_mean)             # points away from the honest cluster
    peer_scale ← median( ||peer_i - peer_mean|| )

    if mode == "min_max":
        threshold ← max pairwise Euclidean distance among peers
        feasible(c) ← ( max_i ||peer_i - c|| ≤ threshold )
    elif mode == "min_sum":
        threshold ← max_i ∑_j ||peer_i - peer_j||²
        feasible(c) ← ( ∑_i ||peer_i - c||² ≤ threshold )

    lo, hi ← 0, gamma_max · peer_scale
    repeat 30 times:                                    # binary search on the boundary radius
        mid ← (lo + hi) / 2
        if feasible(peer_mean + mid · direction): lo ← mid
        else:                                     hi ← mid

    gamma     ← lo · clip(strength, 0, 1)              # strength == "aggressiveness" from Algorithm 2
    return peer_mean + gamma · direction                # the crafted malicious update
Intuition: the attack doesn't perturb the target's own genuine update — it recenters on the observed peer mean and pushes as far as possible in the direction that hurts the global model most, stopping exactly where the defense's own admissibility test (max pairwise distance for min_max, sum-of-squared distance for min_sum) would start rejecting it. This is why these attacks structurally require the Peer Fingerprint Registry and cannot run target-update-only, unlike sign_flip/scale/noise.
